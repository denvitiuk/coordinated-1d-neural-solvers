# Отчёт: метод координации одномерных задач — оптимизация и обобщение

Дата: 2026-11-10. Все числа получены на этом компьютере (Apple Silicon, CPU float64,
и для сравнения GPU MPS float32). Повторить: `python plate_benchmark.py`,
проверки: `python checks/run_checks.py` (все проходят).

## 1. Задача

Пластина 5 × 12 из диплома: −T_xx − T_yy = 0, боковые стороны теплоизолированы
(∂T/∂n = 0), сверху T = 60·cos(πx/5), снизу T = 20·sin(πx/5). Сетка 51 × 121
(как в тексте диплома): 5831 неизвестная.

Метод координации: вместо одной большой системы решаем два семейства независимых
одномерных задач

    (L_x + s) u = −q   — 119 систем по 49 уравнений (вдоль x),
    (L_y − s) v =  q + g — 49 систем по 119 уравнений (вдоль y),

и подбираем функцию-координатор q так, чтобы u = v, минимизируя
J(q) = ½‖u − v‖². При u = v сумма уравнений даёт ровно 5-точечную схему (6) диплома.

Сдвиг s добавлен потому, что при теплоизолированных боковых сторонах матрица L_x
вырождена (условия Неймана с обеих сторон), и постановка (7) диплома без сдвига
не имеет единственного решения. При u = v сдвиги сокращаются — ответ не меняется.
Выбрано s = λ_min(L_y)/2.

## 2. Что сделано

1. **Прогонка без цикла Python.** У всех строк одна и та же матрица, поэтому
   разложение A = L·U (по сути метод квадратного корня из диплома) строится
   один раз, а решение всех 119 (или 49) систем — две треугольные подстановки
   одним вызовом BLAS. Одна прогонка стала в 7–15 раз быстрее.
2. **Предобусловливание по переменным направлениям (ADI).** Без него число
   итераций растёт пропорционально 1/h (315 → 564 → 1001 при измельчении сетки).
   Из алгебры задачи: M = X⁻¹ + Y⁻¹, значит M⁻¹ = Y·(X + Y)⁻¹·X, а (X + Y)⁻¹
   приближается шестью шагами метода Писмена — Рэкфорда. Каждый шаг — снова
   прогонки вдоль x и вдоль y, т.е. идея диплома (только одномерные независимые
   задачи) сохраняется полностью. Внешний метод — GMRES с правым
   предобусловливанием: он минимизирует именно ‖u − v‖, поэтому J монотонно
   убывает на каждой итерации (это проверяется в коде).
3. **Общий случай — K подсистем-«чёрных ящиков»** (`multi_coordination.py`):
   A_k u_k = D_k q + F_k, цель J = ½ Σ_{i<j} ‖E_i u_i − E_j u_j‖²
   (при K = 2 это J диплома). Координатору не нужны матрицы подсистем —
   только «реши A_k x = b» и «реши A_kᵀ x = b». Подсистемы могут считаться
   на разных машинах: между ними ходят только векторы.

## 4. Имеет ли это смысл — честно

**Да, для того, ради чего метод задуман:**
- Число итераций с ADI практически не зависит от размера сетки — это главное
  условие, чтобы метод вообще был применим к большим задачам.
- Вся работа — независимые одномерные прогонки: их можно раздать ядрам GPU
  или разным компьютерам. Это и есть цель диплома.
- Общая формулировка с «чёрными ящиками» позволяет координировать
  разнородные подсистемы (разные области, разные модели, разные машины) —
  это классическая идея Лионса, на которого ссылается диплом, в рабочем виде.

**Ограничения, о которых надо знать:**
- Для *этой конкретной* пластины (постоянные коэффициенты, прямоугольник) есть
  специальные прямые методы (разложение по собственным векторам / БПФ), которые
  на малых сетках быстрее: на 51 × 121 мой эталон считает за 0.002 с против
  0.022 с у координации. На 201 × 481 координация уже быстрее этого эталона
  (0.17 с против 0.21 с), но эталон реализован не оптимально, так что это
  не доказательство превосходства над лучшими прямыми методами.
  Смысл метода — там, где прямые методы не работают: переменные коэффициенты,
  сложная геометрия, нелинейность, 3D, распределённый счёт.
- ADI-предобусловливание сейчас сделано для случая DX, DY = const·I (как в
  Лапласе). В общем случае K подсистем без предобусловливания CGLS медленный
  (857 итераций для пластины). Для каждой новой задачи нужен свой
  предобусловливатель — это следующий исследовательский шаг.
- GPU (MPS) на этих размерах медленнее CPU (0.77 с против 0.17 с на 201 × 481)
  и во float32 даёт точность ~1e−3 при T до 60. GPU начнёт выигрывать на
  существенно больших сетках или в 3D; для этого стоит перейти на
  циклическую редукцию и смешанную точность.

## 5. Что найдено в тексте диплома (стоит исправить)

- Формула шага (30): знак — правильно α = −⟨r, φ + ψ⟩ / ‖φ + ψ‖² = ‖p‖²/‖Mp‖²
  (с φ − ψ из текста на примере coordsys2 получается α = −15 и J растёт 0.43 → 3.44).
- `coordsys2.py` использует шаг FUNC/‖GR‖², а не (30); `D1` не обновляется.
  Код из приложения сходится за 277 итераций, а не за 26 из распечатки.
- Для пластины с теплоизолированными сторонами A_k вырождены (не «додатньовизначені»).
- Опечатки в (14)–(16), (20), (25)–(26); 51 × 121 даёт 5831 неизвестную
  (119 систем по 49 и 49 по 119), а не 6000; в распечатке NY = 37, в коде 36.
